# 当前实现参考

> 这份文档是对仓库当前代码的事实整理，不是新的玩法设计稿。结论来自 `src/core/`、`app/src/`、`scripts/` 和自动化测试；如果旧设计稿与这里冲突，以代码和测试结果为准。审查日期：2026-08-02。

| 内容 | 当前事实来源 | 备注 |

## 2. 运行时结构

- 产品入口是 `app/` 下的 React 19 + Vite 应用；根目录脚本通过 `npm --prefix app` 代理构建、开发和预览。
- 规则引擎位于 `src/core/`，由 `TurnManager` 编排 `SeasonCycle`、`QiManager`、`ScoreManager`、`HandManager`、`CardPoolManager` 和 `LeverageCalculator`。
- `app/src/store.ts` 只负责把核心状态同步到 React，并管理选择、结算预览和动画事件；UI 不应自行复制经济常量。
- 运行时固定为单机 Web 游戏；当前没有联网、多人、AI 对手或微信小游戏适配实现。

## 3. 当前默认数值

以下全部来自 `DEFAULT_BALANCE_CONFIG` 和 `ScoreManager` 的静态常量：

| 参数 | 值 | 代码位置 |
|---|---:|---|
| 总回合 | 60 | `TurnManager.TOTAL_ROUNDS` |
| 手牌槽位 | 3 | `HandManager.MAX_HAND_SIZE` |
| 气上限 / 初始气 | 80 / 50 | `BalanceConfig.ts` |
| 每回合自然回气 | 10 | `baseRecovery` |
| 等待额外回气 | 10 | `waitBonus` |
| 买入基数 / 评分系数 | 11 / 0.05 | `baseBuyCost`、`buyCostFactor` |
| 杠杆买入附加消耗 | 8 | `lqc` |
| 买入入场手续费 | 2 | `buyEntryFee` |
| 卖出退出费 | 4 | `sellCost` |
| 持仓收益系数 | 1.2 | `ScoreManager.HOLD_BONUS` |
| 卖出价差系数 | 4 | `ScoreManager.SPREAD_MULTIPLIER` |
| 持仓基础气耗 | `max(0.5, 1.5 + 0.4 × 当季评分)` | `holdQiBase`、`holdQiScoreFactor`、`holdQiMin` |
| 杠杆额外持仓气耗 | `杠杆倍率 × 1`（仅倍率大于 1 时） | `leverageQiCostPerX` |
| 强平返还系数 | 0.5 | `forcedLiquidationQiReturnFactor` |
| 强平正收益折算 | 0.8 | `forcedLiquidationScoreMultiplier` |
| 强平扣分系数 | 6 | `marginCallPenaltyPerScore` |

公式：

```text
买入气耗 = ceil(11 × (1 + 0.05 × 买入时当季评分) + (是否杠杆 ? 8 : 0))
锁定气 = 买入气耗 - 2
持仓气耗 = max(0.5, 1.5 + 0.4 × 当前结算季评分) + (杠杆 > 1 ? 杠杆 × 1 : 0)
持仓收益 = 1.2 × 当前结算季评分 × 有效杠杆
卖出得分 = (当前评分 - 买入评分) × 4 × 有效杠杆
```

主动卖出先释放锁定气（总气最高封顶 80），再扣 4 气退出费；卖出本身不额外奖励气。锁定气不是第二个气池，也不会把气上限改成 `80 - lockedQi`。

## 4. 卡牌与评分

### 4.1 牌池数据

- 当前运行时加载 60 张 ID 1–60 的甲子牌。
- 每张牌包含 `name`、天干、地支、天干五行、地支五行、主五行和阴阳。
- 主五行等于天干五行；阴阳按数据文件保存，默认 fallback 也按 ID 奇阳偶阴生成。
- 地支藏干表和干支关系目前写在 `JiaziCard.ts` 的评分实现中，并不是 JSON 字段。

### 4.2 当季评分

`JiaziCard.getSeasonScore()` 先计算四季原始评分平均值，再以平均值为中心施加阴阳系数：

```text
raw = 0.5 × 天干季节分 + 0.3 × 地支藏干季节分 + 0.2 × 干支关系分
最终当季评分 = round(0.02 + 阴阳系数 × (当前季 raw - 四季 raw 均值), 2)
阳系数 = 1.1；阴系数 = 0.9
```

单层五行季节分的当前实现是：土 `+1`；当季元素 `+4`；同组（木火或金水）`+2`；对立（木金、火水）`-4`；其他跨组 `-2`。干支关系分是同元素 `+2`、同组 `+1.5`、对立 `-2`、其他 `0`。

这意味着当前实现已经包含地支藏干、干支关系和阴阳差异；它不是只有“主五行 × 季节”的四档表。尚未实现的是独立的组合联动加成系统（例如额外的 `CombinationBonus` 配置）。

## 5. 季节与杠杆

- 季节顺序固定为春 → 夏 → 秋 → 冬 → 春。
- 开局一次生成一组季节段：段数随机为 5–20，每段 3–12 回合，总和恰好 60；因此玩家不能从界面反推出本季总长度。
- 玩家可见当前季节和“本季第 N 回合”，不应把当前季总长度作为公开信息。
- 当前杠杆表（`BalanceConfig.leverageTable`）：

| 季内回合 | 有效杠杆 |
|---|---:|
| 1–2 | 1.0x |
| 3–5 | 2.0x |
| 6–8 | 2.5x |
| 9–11 | 3.0x |
| 12 | 3.5x |

只有买入时开启杠杆的仓位会跟随当前季内回合使用上述有效倍率；普通仓位始终按 1.0x。换季时杠杆按新季第 1 回合重新为 1.0x。仓位保存买入时倍率仅用于存档和显示上下文，结算时会重新读取当前季内回合倍率。

## 6. 牌池、手牌和行动

### 牌池

1. 初始化时复制 60 张牌并 Fisher–Yates 洗牌。
2. 每个玩家行动回合从牌堆顶部抽最多 2 张到公共牌池。
3. 买入一张后，未选公共牌随机插回牌堆；被买入的牌离开牌堆，直到主动卖出或强平后才回到牌堆。
4. 等待时，所有公共牌随机回牌堆。

### 手牌

- 固定 3 个槽位；买入写入第一个空槽位。
- 每个仓位记录：牌、买入评分、是否杠杆、买入时有效倍率、买入回合、锁定气和累计持仓收益。

### 玩家行动

- 每回合只能选择一个：买入、卖出、等待。
- 第 60 回合不允许买入；第 60 回合确认卖出或等待后直接结束，不再构造第 61 回合持仓结算或回气。
- 买入、卖出和等待都先进入结算预览；点击“返回修改”不会改变核心状态，点击确认后才调用对应 `execute*` 方法。

## 7. 精确回合顺序

`TurnManager.processRound()` 的实际顺序是：

1. 如果当前回合超过 60，进入 `game_over`。
2. 结算当前手牌：按当前季节评分加分、扣持仓气耗，并在扣气后检查强平。
3. 抽最多 2 张公共牌。
4. 恢复 10 气；若上一回合选择等待，再恢复 10 气；回复最高到 80。
5. 进入 `player_action`，等待玩家提交一次行动。
6. 行动确认后推进总回合和季内回合；必要时切换季节，再处理下一回合。

所以界面上的“下一回合结算预览”是对下一次 `processRound()` 的预测，不是把已经发生的结算再弹一次。

## 8. 强平规则

强平判定发生在持仓气耗扣除之后，条件为当前气 `<= 0`。如果没有杠杆仓位，系统不会凭空强平普通仓位；如果存在杠杆仓位，当前实现从候选中随机选择一张：

- 移除该杠杆仓位并把牌随机回牌堆。
- 不收主动卖出退出费，也不提供主动卖出的即时回气。
- 正卖出价差按 0.8 向下取整；负价差不打折。
- 额外扣分：`round(当前杠杆 × |当前评分| × 6)`，总分最低为 0。
- 返还 `floor(锁定气 × 0.5)`，上限仍为 80。

当前实现一次结算最多处理一张强平牌；这与旧设计稿中“循环强平直到气转正”的描述不同，后续若要改动必须先更新代码与测试，再更新本文件。

## 9. 当前界面实现

- `App.tsx` 组合顶部回合/季节与分数、气条、公共牌池、手牌、底部行动栏、结算预览、季节过渡、强平反馈和游戏结束层。
- 顶部显示总回合 `第 N/60 回合`、当前季内回合和进度条；不显示本季总长度。
- 分数面板显示总分与“本回合”分数变化；“累计总分”冗余标签已移除。
- 评分和季节使用五行主题色；帮助按钮位于公共牌池标题栏，打开短帮助弹窗。
- 卡牌显示天干、地支、当前到下一季评分趋势、买入/持仓/累计信息和紧凑杠杆标签。
- 三张手牌和结算预览在已覆盖的窄屏/短屏场景中不产生页面滚动；布局由 `app/src/index.css` 的短屏规则压缩。

## 10. 存档与模拟验证

- `TurnManager.saveGame()` 将当前回合、状态、气、分数、统计、季节段长度、手牌字段和牌池 ID 写入浏览器 `localStorage` 的 `jiazi_game_save`。
- `loadGame()` 会校验基本字段，并兼容缺失 `lockedQi` 的旧存档；无法还原时清理坏档并返回失败。
- `scripts/simulator.py` 读取同一份 JSON 牌库并镜像当前核心常量；`tests/integration/simulator_parity.test.ts` 和 `scripts/test_simulator.py` 用于验证模拟器与核心行为的关键一致性。

## 12. 已发现的文档漂移

审查时确认下列旧文档内容与当前实现不一致，暂不把它们当作运行时事实：

| 旧内容 | 当前实现 | 处理原则 |
|---|---|---|
| Phaser 3 架构、Canvas/Scale Manager | React 19 + Vite + CSS | 旧架构文档视为历史设计稿 |
| 杠杆 1.0 → 1.5 → 2.0 → 2.5 → 3.0 | 1.0 → 2.0 → 2.5 → 3.0 → 3.5 | 以 `BalanceConfig` 和测试为准 |
| 杠杆买入附加 14 气 | 当前为 8 气 | 以 `lqc` 为准 |
| 等待按钮 +17 气 | 当前为自然 10 + 等待 10 | 以 `baseRecovery + waitBonus` 为准 |
| `80 - totalLockedQi` 的动态气上限 | 当前气上限固定 80，锁定气只是总气子集 | 以 `QiManager` 为准 |
| 卖出返还/保证金术语 | 当前产品文案使用“锁定气/释放占用气” | 以 `CONTEXT.md` 的统一语言为准 |
| 当前仓库版本元数据 `package.json=0.1.0` 与项目状态中的 MVP 0.2.0 | 两者尚未统一 | 这是待确认的版本发布问题，不能擅自推断已发布 0.2.0 |
