# AI 行为规范

> 定义 AI 在项目中的行为边界：该做与不该做

---

## 一、核心理念

```
用户驱动协作，而非自主执行。
每个任务遵循：提问 → 选项 → 决策 → 草稿 → 批准
```

---

## 二、该做清单（MUST）

### 2.1 进入项目时

- [ ] 首先读取 `production/session-state/active.md` 恢复上下文
- [ ] 确认当前任务状态和进度
- [ ] 检查是否有待用户决策项

### 2.2 编写代码时

- [ ] 所有 gameplay 数值必须从配置文件读取，禁止硬编码
- [ ] 添加 JSDoc 格式的文档注释
- [ ] 遵循 `docs/rules/` 下对应领域的规则
- [ ] 修改文件前先读取确认当前内容

### 2.3 提交变更时

- [ ] 更新 `production/session-state/active.md` 状态
- [ ] 记录操作到 `production/session-logs/session-log.md`
- [ ] 用户决策记录到 `production/decision-log/decisions.md`
- [ ] 等待用户确认后再执行 git commit

### 2.4 遇到问题时

- [ ] 明确告知用户遇到的问题和阻塞原因
- [ ] 提供多个可行选项供用户选择
- [ ] 记录问题和解决方案到会话状态

---

## 三、不该做清单（MUST NOT）

### 3.1 代码修改

- [ ] **禁止**自行提交代码到 git（需用户确认）
- [ ] **禁止**硬编码 gameplay 数值
- [ ] **禁止**修改 `docs/rules/` 下的规则文件（用户专属）
- [ ] **禁止**删除或移动文件结构（需用户批准）

### 3.2 决策权限

- [ ] **禁止**自行做出方向性决策
- [ ] **禁止**跳过用户审批流程
- [ ] **禁止**修改用户已确认的决策记录

### 3.3 文件操作

- [ ] **禁止**访问 `docs/rules/file-access.md` 中标记为禁止的目录
- [ ] **禁止**在用户未确认时创建新文件
- [ ] **禁止**批量删除文件

### 3.4 沟通方式

- [ ] **禁止**模拟或伪造数据（如 Mock API 响应）
- [ ] **禁止**在代码中添加表情符号（除非用户明确要求）
- [ ] **禁止**过度赞美或使用"你完全正确"等表述

---

## 四、行为决策流程

```
┌─────────────────────────────────────────────────────────────┐
│                      行为决策流程                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 接收任务                                                │
│     ↓                                                       │
│  2. 检查文件权限 @docs/rules/file-access.md                │
│     ↓                                                       │
│  3. 检查行为边界（本文档）                                  │
│     ↓                                                       │
│  4. 是否涉及方向性决策？                                    │
│     ├── 是 → 提供选项 → 等待用户决策                       │
│     └── 否 → 执行操作 → 记录日志                           │
│     ↓                                                       │
│  5. 更新会话状态                                            │
│     ↓                                                       │
│  6. 等待用户确认或下一步指令                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 五、紧急情况处理

### 5.1 遇到无法解决的问题

1. 明确告知用户问题所在
2. 记录到 `production/session-state/active.md` 的阻塞项
3. 提供可能的解决方向供用户选择

### 5.2 用户指令与规范冲突

1. 告知用户该指令与现有规范冲突
2. 说明冲突的具体内容
3. 等待用户明确确认是否继续
4. 用户坚持执行则记录为临时决策

### 5.3 发现代码问题

1. 记录问题到会话状态
2. 提出修复建议
3. 等待用户确认后执行

## 六、协作检查清单

### 6.1 会话开始检查

AI 进入项目时必须完成：

- [ ] 读取 `production/session-state/active.md` 恢复上下文
- [ ] 确认当前任务状态和进度
- [ ] 检查是否有待用户决策项
- [ ] 检查是否有阻塞项需要处理
- [ ] 向用户汇报当前状态

### 6.2 会话进行中检查

AI 在会话过程中必须：

- [ ] 每次文件操作后记录到操作日志
- [ ] 用户决策立即记录到决策日志
- [ ] 保持会话状态文件为最新
- [ ] 遇到问题主动汇报，不隐瞒

### 6.3 会话结束审计（强制）

AI 在每次会话结束前**必须完成以下审计**：

#### 状态更新
- [ ] 更新 `production/session-state/active.md` 任务状态
- [ ] 记录本会话所有文件变更
- [ ] 更新 `production/session-logs/session-log.md`
- [ ] 更新 `production/decision-log/decisions.md`（如有新决策）

#### 闭环验证
- [ ] 任务状态与实际进度一致
- [ ] 所有变更已列出
- [ ] 阻塞项已明确标注（如有）
- [ ] 待用户决策项已列出（如有）

#### 恢复准备
- [ ] 快速恢复步骤已更新
- [ ] 下一步计划已明确

### 6.4 审计不通过处理

如果审计不通过，AI 必须：

1. 立即补充缺失的记录
2. 更正不一致的状态
3. 完成后再请求用户确认
4. 禁止在审计不通过时结束会话

## 七、禁止行为清单

### 7.1 绝对禁止

| 行为 | 后果 |
|------|------|
| 跳过用户确认直接提交代码 | 违规记录，需回滚 |
| 修改用户已确认的决策日志 | 违规记录，需恢复 |
| 删除文件未告知用户 | 违规记录，需恢复 |
| 伪造操作日志 | 严重违规，需人工审查 |
| 未完成审计结束会话 | 违规记录 |

### 7.2 违规记录格式

```markdown
## 违规记录

- **时间**: YYYY-MM-DD HH:MM
- **违规行为**: [描述]
- **影响范围**: [文件/功能]
- **处理方式**: [回滚/恢复/人工审查]
- **责任人**: [AI 会话ID]
```
