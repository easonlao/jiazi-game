# 文件访问权限矩阵

> 定义 AI 对各目录的访问权限：可读/可写/禁止

---

## 一、权限等级说明

| 权限 | 标识 | 说明 |
|------|------|------|
| **只读** | `R` | 可读取，不可修改 |
| **可读写** | `RW` | 可读取和修改 |
| **需确认** | `R?` | 可读取，修改需用户确认 |
| **禁止** | `X` | 禁止访问 |

---

## 三、特殊规则

### 3.1 新建文件

| 目录 | 新建权限 | 说明 |
|------|----------|------|
| `tmp/` 及子目录 | `RW` | **可自由新建**，用于临时调试、实验性代码 |
| `src/` 子目录 | `R?` | 新建代码文件需用户确认 |
| `tests/` 子目录 | `R?` | 新建测试文件需用户确认 |
| `design/gdd/` | `R?` | 新建 GDD 需用户确认 |
| `docs/` | `R?` | 新建文档需用户确认 |
| 根目录 | `X` | 禁止在根目录新建文件 |

**新建文件规则**：
1. **临时调试文件**：可在 `tmp/` 目录自由创建，无需用户确认
2. **项目代码文件**：新建 `src/` 下文件需用户确认
3. **测试文件**：新建 `tests/` 下文件需用户确认
4. **升级流程**：`tmp/` → `tests/` 或 `tmp/` → `src/` 时需用户确认

### 3.2 删除文件

- **任何删除操作都需要用户明确确认**
- 删除前必须在会话状态中记录原因
- 用户确认后方可执行

### 3.3 重命名/移动

- **任何重命名/移动操作都需要用户明确确认**
- 必须同步更新所有引用该文件的代码
- 用户确认后方可执行

## 四、权限检查流程

```
┌─────────────────────────────────────────────────────────────┐
│                     权限检查流程                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 确定目标文件/目录                                       │
│     ↓                                                       │
│  2. 查询本文件权限矩阵                                      │
│     ↓                                                       │
│  3. 判断操作类型（读/写/新建/删除）                         │
│     ↓                                                       │
│  4. 权限检查                                                │
│     ├── RW → 执行操作                                       │
│     ├── R? → 告知用户，等待确认                             │
│     ├── R → 只读，禁止写入                                  │
│     └── X → 禁止访问，告知用户                              │
│     ↓                                                       │
│  5. 记录操作到会话日志                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 五、违规处理

如果 AI 尝试执行无权限的操作：

1. 操作将被阻止
2. 记录违规行为到会话日志
3. 告知用户违规原因
4. 提供正确的操作流程

---

## 六、权限更新

本权限矩阵由**用户维护**，AI 不可自行修改。

如需调整权限，用户应：
1. 直接编辑本文件
2. 在决策日志中记录变更原因
3. 告知 AI 新的权限规则
