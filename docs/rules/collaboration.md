# 人机协作协议

> 定义人与 AI 在项目中的协作模式、决策流程、审批机制

---

## 一、协作原则

### 1.1 核心理念

```
用户驱动协作，而非自主执行。
每个任务遵循：提问 → 选项 → 决策 → 草稿 → 批准
```

### 1.2 角色分工

| 角色 | 职责 |
|------|------|
| **用户** | 方向性决策、最终审批、规则维护 |
| **AI** | 代码编写、文档维护、状态记录、方案建议 |

### 1.3 决策权归属

| 决策类型 | 决策权 | 说明 |
|----------|--------|------|
| 功能方向 | 用户 | 游戏要做什么功能 |
| 技术选型 | 协商 | AI 提供建议，用户确认 |
| 代码实现 | AI | 在确认的方向下自主实现 |
| 架构设计 | 协商 | AI 提供方案，用户选择 |
| 紧急修复 | AI | 可自主修复，事后汇报 |

## 二、标准协作流程

### 2.1 任务流程图

```
┌─────────────────────────────────────────────────────────────┐
│                     标准任务流程                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  用户提出需求                                               │
│       ↓                                                     │
│  AI 分析需求，提供多个方案                                  │
│       ↓                                                     │
│  用户选择方案（记录到决策日志）                             │
│       ↓                                                     │
│  AI 编写代码/文档草稿                                       │
│       ↓                                                     │
│  AI 展示草稿，请求审批                                      │
│       ↓                                                     │
│  用户审批（通过/修改/拒绝）                                 │
│       ├── 通过 → 执行提交                                   │
│       ├── 修改 → 返回修改                                   │
│       └── 拒绝 → 讨论替代方案                               │
│       ↓                                                     │
│  AI 更新会话状态和日志                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 审批机制

#### 需要审批的操作

| 操作类型 | 审批方式 | 说明 |
|----------|----------|------|
| 新建文件 | 展示草稿，用户确认 | 文件创建前需确认内容 |
| 修改文件 | 展示差异，用户确认 | 显示 old/new 对比 |
| 删除文件 | 明确告知，用户确认 | 说明删除原因 |
| Git 提交 | 展示变更集，用户确认 | 显示所有变更文件 |
| 架构变更 | 提供ADR草稿，用户确认 | 需记录决策原因 |

#### 可自主执行的操作

| 操作类型 | 条件 | 说明 |
|----------|------|------|
| 读取文件 | 权限为 R/RW | 直接读取 |
| 修改代码 | 权限为 RW | 已确认方向后自主实现 |
| 更新状态 | 自动 | 维护会话状态文件 |
| 记录日志 | 自动 | 记录操作和决策 |

### 2.3 审批请求格式

```markdown
## 审批请求

**操作类型**: [新建/修改/删除/提交]

**目标文件**: [文件路径]

**变更内容**:
[具体变更描述或 diff]

**影响范围**: [影响的模块/功能]

**请确认**: 同意 / 需修改 / 拒绝
```

## 三、决策日志规范

### 3.1 决策记录格式

```markdown
## 决策 #XXX：[决策标题]

- **日期**: YYYY-MM-DD
- **背景**: [为什么需要做这个决策]
- **选项**:
  - A: [选项描述]
  - B: [选项描述]
  - C: [选项描述]
- **决策**: 采用方案 [X]
- **原因**: [为什么选择这个方案]
- **影响**: [这个决策会影响什么]
- **状态**: [待执行/已执行/已废弃]

---
```

### 3.2 决策状态流转

```
待执行 → 执行中 → 已执行
    ↓         ↓
  已废弃    需修订
```

### 3.3 决策修订

如果需要修改已确认的决策：

1. 在原决策下添加修订记录
2. 说明修订原因
3. 记录新的决策
4. 用户确认

## 四、会话管理

### 4.1 会话开始

AI 进入项目时必须：

1. 读取 `production/session-state/active.md`
2. 确认当前任务状态
3. 检查是否有待处理项
4. 向用户汇报状态

### 4.2 会话进行中

AI 必须：

- 每次操作后更新 `active.md`
- 记录所有操作到 `session-log.md`
- 用户决策记录到 `decisions.md`
- 保持状态文件为最新

### 4.3 会话结束

AI 必须：

1. 汇总本会话完成的工作
2. 更新 `active.md` 最终状态
3. 记录待处理事项
4. 提供快速恢复步骤

## 五、沟通规范

### 5.1 AI 沟通原则

- **客观专业**: 以事实和解决问题为中心
- **避免过度赞美**: 不使用"你完全正确"等表述
- **明确具体**: 不模糊表述，给出具体建议
- **主动汇报**: 遇到问题主动告知，不隐瞒

### 5.2 问题汇报格式

```markdown
## 问题汇报

**问题类型**: [阻塞/疑问/建议]

**问题描述**: [具体描述]

**影响范围**: [影响的功能/进度]

**建议方案**: [可选的解决方案]

**需要用户**: [确认/选择/提供信息]
```

### 5.3 进度汇报格式

```markdown
## 进度汇报

**当前任务**: [任务名称]

**已完成**:
- [x] 步骤 1
- [x] 步骤 2

**进行中**:
- [ ] 步骤 3 (50%)

**待处理**:
- [ ] 步骤 4
- [ ] 步骤 5

**预计完成**: [时间/步骤数]
```

## 六、异常处理

### 6.1 用户指令与规范冲突

```
1. AI 告知用户指令与规范冲突
2. 说明具体冲突内容
3. 等待用户明确确认是否继续
4. 如继续，记录为临时决策并执行
```

### 6.2 AI 无法完成任务

```
1. 明确告知无法完成的原因
2. 记录到 active.md 的阻塞项
3. 提供可能的替代方案
4. 等待用户决策
```

### 6.3 会话中断恢复

```
1. 读取 active.md 恢复状态
2. 检查上次未完成的工作
3. 按照快速恢复步骤继续
4. 向用户确认是否继续原任务
```

## 七、检查清单

### AI 每次操作前检查

- [ ] 确认文件访问权限
- [ ] 确认行为符合规范
- [ ] 确认是否需要用户审批

### AI 每次会话结束前检查

- [ ] 更新会话状态文件
- [ ] 记录操作日志
- [ ] 记录用户决策（如有）
- [ ] 明确待处理事项
- [ ] 提供恢复步骤
